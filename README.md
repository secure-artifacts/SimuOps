# SimuOps Auto Manager Pro

`SimuOps Auto Manager Pro` 是一个面向 `Windows` 的可视化桌面自动化工具，核心能力是通过模拟鼠标、键盘、窗口切换、文件拖拽和图片识别，自动执行原本需要人工一步步完成的软件操作流程。

它最大的价值，不在于依赖某个软件是否开放 `API`，而在于直接模拟人的操作方式，对各种桌面软件、浏览器页面、后台系统、上传界面和重复性任务进行批量自动化处理。

## 项目定位

很多业务软件并没有开放接口，也不支持脚本调用，但人工操作路径往往是固定的，例如：

- 打开指定软件或网页
- 点击某个按钮
- 输入文字或粘贴内容
- 上传图片、文件或附件
- 切换窗口或激活目标程序
- 根据界面变化继续执行下一步
- 重复执行几十次、几百次相同流程

这个项目的目的，就是把这类“人工点点点”的操作整理成可复用流程，再结合批量数据，实现一键批量执行。

## 核心特点

- 模拟人工操作：通过鼠标点击、双击、右键、移动、键盘输入、快捷键和滚轮控制，直接驱动目标软件界面。
- 无需目标软件开放接口：适合没有 API、只能手工操作的桌面软件、网页后台和管理系统。
- 批量执行能力强：同一套流程可以配合多组数据反复运行，适合大批量重复任务。
- 可视化编排：通过界面配置步骤，不需要手写复杂脚本。
- 兼顾自动与人工接管：执行中支持暂停、恢复、跳步、重试、下一行和停止。
- 适用软件范围广：适合浏览器页面、Windows 客户端、上传窗口、管理后台、资料录入软件等场景。

## 主要功能

- 流程编排：通过可视化步骤组合自动化流程，支持点击、双击、右键、移动鼠标、键盘输入、组合键、滚轮滚动、等待等基础操作。
- 文本输入增强：支持普通输入、清空后输入、增强输入、剪贴板粘贴，适合处理长文本、多行文本和重复录入任务。
- 图片识别与条件判断：支持找图点击、找图判断、窗口存在判断，可用于根据界面状态执行不同分支。
- 文件处理能力：支持上传文件、拖拽文件、选择素材路径、自动截图，适合图片上传、附件提交和取证留档场景。
- 窗口与程序控制：支持激活窗口、打开网址、运行程序、执行 CMD 指令，方便把网页与本地软件串起来。
- 批量数据驱动：内置批量数据表，可按行执行任务，把同一套流程批量应用到不同账号、文本、文件或参数上。
- 智能填充：支持扫描文件夹、按规则识别图片和文本文件，并自动填入批量数据表，减少手工整理数据的时间。
- 任务管理：支持新建任务、任务分类、重命名、克隆、移动和删除，适合维护多套不同业务流程。
- 排程与定时：支持计划时间、任务排程包、序列化排程执行，方便在指定时间自动启动任务。
- 执行控制：支持试运行、正式运行、暂停、恢复、停止、跳步、下一行、重试，并带有执行日志和进度状态显示。
- 辅助工具：内置窗口选择器、Chrome 账户选择、CMD 预设中心、常用前缀库、截图工具等配套能力。

## 适用场景

- 批量操作各种 Windows 软件
- 自动填写网页或桌面表单
- 批量上传图片、附件、素材
- 多账号重复登录与处理任务
- 重复点击、切换、输入、提交类工作
- 没有 API、只能人工操作的软件自动化
- 需要按固定流程批量处理数据的业务场景

## 运行环境

- 操作系统：`Windows 10 / Windows 11`
- Python：`3.11` 或更高版本
- 架构：推荐 `64 位`
- GUI 框架：`PyQt5`

## 安装步骤

### 方法一：直接使用仓库内脚本安装

1. 安装 `Python 3.11+`
2. 将项目下载或克隆到本地
3. 进入项目目录
4. 双击运行 `setup.bat`
5. 安装完成后，双击运行 `start.bat`

这种方式最适合普通用户，项目会自动创建本地虚拟环境并安装所需依赖。

### 方法二：手动安装

如果你希望自己控制环境，可以使用命令行手动安装：
python -m venv .venv .venv\Scripts\activate python -m pip install --upgrade pip pip install -r requirements.txt python main.pyw


## 快速开始

1. 启动程序后，先新建一个任务。
2. 在“流程编排”页面添加自动化步骤。
3. 如果需要批量执行，在“批量数据”页面准备多行数据。
4. 先用“试运行”检查流程是否正常。
5. 确认无误后，点击“启动批量任务”开始执行。
6. 如需定时执行，可在“任务排程”中配置执行时间和任务顺序。

## 基本使用流程

1. 创建任务：建立一套新的自动化流程。
2. 添加步骤：配置点击、输入、等待、找图、打开网址、运行程序、上传文件等动作。
3. 设置数据：为不同执行对象准备批量数据。
4. 测试流程：用少量数据试跑，确认界面坐标、窗口和识别逻辑正确。
5. 正式执行：按数据表批量运行整套流程。
6. 监控执行：通过日志、进度条和浮窗状态随时观察任务执行情况。

## 项目文件

- `main.pyw`：主程序入口
- `requirements.txt`：Python 依赖列表
- `setup.bat`：初始化虚拟环境并安装依赖
- `start.bat`：启动程序
- `config.default.json`：默认配置模板
- `command_presets.json`：CMD 指令预设
- `input_prefixes.json`：输入前缀库
- `.gitignore`：Git 忽略规则

## 配置文件说明

- `app_config.json`：程序运行后生成的本地主配置文件
- `command_presets.json`：保存自定义 CMD 预设
- `input_prefixes.json`：保存常用输入前缀
- `logs/`：执行或调试过程中产生的日志目录
- `screenshots/`：自动截图保存目录
- `captures/`：截图或识别辅助文件目录

其中 `app_config.json`、日志、截图和缓存文件属于本地运行数据，通常不建议提交到 GitHub。

## 常见问题

### 为什么这个项目更适合 Windows

因为部分能力依赖 Windows 的窗口、输入、拖拽和桌面控制机制，在其他系统上无法保证行为一致。

### 为什么建议先试运行

桌面自动化依赖实际界面位置、窗口状态、分辨率、缩放比例和目标软件行为。先试运行可以减少批量执行时的误操作风险。

### 可以完全替代 API 吗

不能一概而论，但对于没有接口、接口不完整、流程依赖图形界面的软件，这种模拟人工操作的方式往往更实用。

## 注意事项

- 本项目主要面向 Windows 桌面环境，部分功能依赖 Windows 的窗口与输入控制能力。
- 首次使用建议先做小范围测试，确认坐标、窗口、图片识别和输入逻辑都符合预期。
- 批量执行前，建议准备专门的测试账号或测试数据，避免误操作正式环境。
- 运行过程中生成的本地配置、日志、截图和缓存文件已通过 `.gitignore` 排除，不建议直接提交到仓库。
- 如需重置本地配置，可删除 `app_config.json` 后重新启动程序。
